### Smoke findings

<!-- Numbered: the failing test (its case ID), whether the app or the test was wrong, the cause, and the fix (commit). -->

1. INV-06 (attempt 4): the app was wrong. The new top bar's scan shortcut was named "Read a barcode", and
   `getByLabel('Code')` matches aria-labels by substring ("bar**code**"), so it found two elements. The shortcut is now
   "Open the reader" ("Abrir el lector"), which no form label contains. Fixed in the 0.5 commit.
2. INV-04, USR-01, INVC-07 (attempt 7): the test was wrong. The smoke stack's Symfony debug toolbar (dev only)
   covered the Move dialog's footer, its panels hold "ROLE_ADMIN", and it matched `getByLabel('To')`. Every page of a
   run now goes without it (`e2e/support/test.ts`, `withoutDebugToolbar`); NAV-05's keyboard workaround is gone.
   INVC-07 also matched "Cus**to**mer…" with `getByLabel('To')`: the date labels are matched with `exact: true`.
3. ORD-01 (attempt 7): the test was wrong. The phone card title ("W00001 · Jose Perez") stays in the DOM on desktop,
   so `getByText('Jose Perez')` found two elements: matched with `exact: true`.
4. ORD-17 (attempt 7): the test was wrong. Only a shipment of the whole order at once sends it
   (`RecordPartialShipmentHandler`, as the legacy code did); the shipment that completes an order leaves it Partial.
   The spec and the case text expect "… is partial." for the second shipment.
5. INV-30 (attempt 7): the app was wrong. At 390 px the scan screen was 418 px wide (534 px in Spanish): its grids'
   auto column grew to the longest line, and the kit's `ActionBar` kept two large buttons on one line. The scan
   grids are `minmax(0, 1fr)` and the action bar's buttons wrap on phones (`shared/ui/styles/kit.css`).
6. INVC-08, ORD-24, INV-18, ORD-32 (attempt 8): the tests were wrong. INVC-08 clicked the phone card title, hidden
   on desktop; ORD-24 matched the name twice (card title and cell): `exact: true`. INV-18: the fixtures' title is the
   code, so the Code cell is taken with `.first()`. ORD-32 expected "Start camera" on the plain-http smoke stack,
   where the camera says why it cannot start (as INV-26 checks): it now expects that note.
7. ORD-26, INV-21 (attempt 9): the tests were wrong. ORD-26 tapped a card lying under the sticky filters / tab bar of
   the phone: the list is narrowed to the order first. INV-21's "Upload a stock sheet" is also the sidebar entry: the
   toast's link is taken inside the `status` region.
8. ORD-26 (attempt 10): the test was wrong. It measured the slide-over's width during its slide-in (389.99 px): it
   now waits for the full width.
